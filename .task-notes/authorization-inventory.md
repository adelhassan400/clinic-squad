# Authorization and Tenant-Isolation Inventory

Audit basis: current Express route registration in `artifacts/api-server/src/routes/index.ts`, route middleware, service queries, and Drizzle schemas. The `users` table stores one `clinicId` and a trusted database role. Clinic-scoped tables include patients, appointments, prescriptions, lab results, finances, cash transactions, subscriptions, and invitations. Superadmin operations are intentionally global.

## Existing role model

Observed persisted roles: `admin`, `doctor`, `assistant`, `secretary`, `nurse`, and `superadmin`. New clinic owners register as `doctor`; demo admin is `admin`; clinic staff invitation schema currently permits `secretary` and `nurse` (frontend also offers `assistant`). No multi-clinic membership table or role-change endpoint exists.

## Authorization rules to enforce

- Validate access-token integrity and expiry, then reload the user from the database for every authenticated request; database role and clinic membership are authoritative.
- Reject blocked users and clinic users whose clinic is not active. Superadmin remains global and can use explicitly scoped clinic operations.
- Ordinary clinic users may access only the single clinic ID stored on their user row. Scope reads, writes, joins, and nested resources by clinic.
- Clinic `admin`/`doctor` roles manage clinical records, team, clinic identity, and finances. Reception roles (`assistant`, `secretary`, `nurse`) retain patient registration/check-in and scheduling workflows but cannot delete patients, change clinical data, or administer team/clinic settings.
- Keep platform-wide admin routes exclusive to `superadmin`; public routes remain limited to health, login/registration/recovery, invitation-token flows, and public pricing.
